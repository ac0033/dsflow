# 报告写法：先分清两份报告

每步形成两份独立报告：主 agent 写验收报告，面向核验与放行；执行 agent 先起草用户报告，主 agent 在验收后审阅并交付，面向用户理解业务结果与技术实现。两个角色由同一个 agent 兼任时，两份报告仍要各写一份：先以执行者身份写清做了什么，再以验收者身份回到产物核对。两份报告引用同一批真实产物和数字，但职责不同；不要把验收清单塞进用户报告，也不要用顺畅叙事替代独立验收。项目已有文件命名时沿用命名，但须能一眼区分两份报告。

计划与报告围绕同一个问题：本步要帮助用户判断什么、取得了什么证据、得到什么结果、后续怎样使用。计划不得预写结果。用户报告按[用户报告写法](user-report.md)组织业务与技术，并参考 Quarto 的文本、代码、执行结果、图像相邻的呈现方式；验收报告按[验收报告写法](acceptance-report.md)记录核验方法、依据和边界。探索性数据分析另读[EDA 用户报告](eda-report.md)，数据变化核对另读[数据变化与验收](data-review.md)。

两份报告都不能编数字或借用未验证的示例。用户报告只呈现已通过验收且影响理解的事实和必要限制；验收报告保留完整判定、失败与证据缺口。若本步未通过，用户报告标为草稿或暂缓交付，先由执行 agent 修正产物，再由主 agent 复验。

写作顺序为：确认本步业务目的与主要发现 → 从真实产物核对数字 → 完成验收报告 → 把经核实的技术原理、主要操作与业务结果写成一条读得懂的故事线 → 检查图表、代码片段、运行结果与正文一致。复杂步骤可分节，简单步骤不必套固定篇幅。
