# 数据变化与验收

先明确每张表的一行代表什么、关联用什么键、字段含义与单位，以及比较期间。按本步操作选择必要检查，不为简单操作堆满统计量。

| 操作或对象 | 核对重点 |
|---|---|
| 行与对象 | 行列数、不同对象数、增加/删除/合并情况、键缺失与唯一性 |
| 字段处理 | 改变行数、原值到新值的规则、缺失原因、类型与单位 |
| 分布变化 | 相关字段的数值或类别分布；前后使用相同范围、单位和分箱 |
| 表关联 | 连接方向、键和预期关系、未匹配原因、是否放大或遗漏行 |
| 数据保全 | 应保留的原列、数量和金额，以及必要的分组和字段关系 |
| 时间可用性 | 字段值及对象关系在预测时点是否已可获取，不能用后来观察代替当时已知 |

未知、冲突和关联失败要区分原因，不一律补零。归一化或合并保留来源与规则映射，检查误合并；范围改变时，把样本范围变化与操作效果分开说明。样例帮助理解，不能代替必要的全量核对。

主 agent 从输入和实际输出独立核对关键约束与业务含义，关键结果用独立计算验证，不把执行者同一函数再跑一次称为独立证明。主 agent 和执行 agent 是同一个 agent 时这条更要守住：验收从落盘的产物重新算，不复用执行时留在内存或中间文件里的结果。在验收报告中说明采用全量、抽样、近似还是代码审查，以及未覆盖范围；用户报告只解释会改变业务理解的主要数据变化。

验收报告如实给出通过、部分通过或失败，并说明理由。发现问题交执行 agent（兼任时就是自己）调整后复验，不擅自改变业务口径、删除数据或覆盖原件。验收通过后审阅并交付用户报告，向用户解释业务结果和关键技术；待用户理解且同意才开始下一步计划。
