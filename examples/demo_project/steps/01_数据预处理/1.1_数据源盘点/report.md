# 1.1 数据源盘点

**结论**：订单明细 `orders.csv` 共 121,000 行 × 12 列，一行 = 一个订单号下的一个 SKU；逐项数出 5 类会影响需求量或金额的质量问题，最多的是 1,000 行完全重复。字段含义清楚，订单里的 SKU 全部能对上目录，可以进入 1.2 清洗。

这一步只读原始文件、不改任何数据，要回答两个问题：每一行、每个字段代表什么；哪些问题会让"按月统计需求量"算错。

## 一行代表什么？字段都是什么意思？

**操作**：逐字段统计类型、缺失、不同值（摘自 [src/inventory.py](src/inventory.py)），结果写在 [field_inventory.csv](outputs/field_inventory.csv)：

```python
for col in orders.columns:
    s = orders[col]
    rows.append({"字段": col, "类型": str(s.dtype), "非空": int(s.notna().sum()), "缺失": int(s.isna().sum()),
                 "不同值": int(s.nunique()), "示例": str(s.dropna().iloc[0])})
```

| 字段 | 类型 | 缺失 | 不同值 | 说明 |
|---|---|---:|---:|---|
| 订单号 | 文本 | 0 | 120,000 | 比行数少 1,000，见下文 |
| 下单时间 | 文本 | 0 | 119,905 | 精确到秒 |
| 类目 | 文本 | 0 | 3 | 办公通用物资、MRO工业品、电力物资 |
| SKU | 文本 | 0 | 3,000 | 与 SKU 目录的 3,000 行对应 |
| 商品名称 | 文本 | 0 | 4,825 | 比 SKU 多，写法不统一 |
| 数量 | 整数 | 0 | 126 | 有负数，是退货行 |
| 单价 | 小数 | 0 | 67,254 | |
| 金额 | 小数 | 641 | 92,033 | 唯一有缺失的字段 |
| 采购单位 / 品牌 / 渠道 / 省份 | 文本 | 0 | 6 / 8 / 3 / 6 | 分组信息，不参与计数 |

**发现**：订单号只有 120,000 个不同值，比 121,000 行少 1,000；去掉 1,000 行完全重复后正好剩 120,000 行。也就是说，在这份数据里每个订单号只有一个订单行，一行 = 一个订单号下的一个 SKU。

## 哪些问题会让需求量算错？

[quality_issues.json](outputs/quality_issues.json) 逐项计数：

| 问题 | 行数 | 会造成什么 | 1.2 怎么处理 |
|---|---:|---|---|
| 完全重复行 | 1,000 | 同一笔需求算两次 | 删除 |
| 未来日期 | 2 | 下单时间落在数据截止月 2026-06 之后 | 删除 |
| 数量为负 | 364 | 退货，不是新的需求 | 标记，是否计入需求量由 2.1 决定 |
| 金额缺失 | 641 | 影响金额，不影响数量 | 标记 |
| 商品名称含首尾空白或全角字符 | 3,733 | 按名称查找时会漏 | 统一写法 |

另外核对了 SKU：订单里的 SKU 全部能在 SKU 目录（3,000 行）里找到，对不上的 0 行。

**例子**：订单号 SO202407017209，下单时间 2024-07-06 05:11:16，SKU01100，数量 4，金额 2744.84——这一行在原始文件里出现了 2 次，所有字段都一样，第二次出现的那行计入"完全重复行"。

**例子**：订单号 SO202407013742 的商品名称写成「Ａ４复印纸 加厚56型　」：全角的 Ａ４，结尾还有一个全角空格。统一写法后是「A4复印纸 加厚56型」。

**注意**：这些是模拟数据里故意放进去的问题（见 [scripts/make_data.py](../../../scripts/make_data.py)）。真实项目里要追问来源，比如重复行是不是某次重复导入造成的。
