# 3.1 按时间切分

**结论**：构造了 SKU×月需求量面板：3,000 个 SKU × 24 个月 = 72,000 行，没有缺月；按月份切成训练期 54,000 行、验证期 9,000 行、最终评估期 9,000 行。面板的需求量合计 547,214，和 1.2 对账一致，可以进入 4.1。

需求预测要回答的是"下个月某个 SKU 要多少"，所以数据的单位要从订单行变成"一个 SKU 的一个月"，而且只能用过去预测未来。

## 为什么要把订单行变成 SKU×月？

订单明细里，一个 SKU 在某个月可能有好几个订单行，也可能一行都没有。预测对象是月度需求量，所以把同一 SKU、同一月份的非退货数量加起来；没有订单的月份不能留空，要记为 0——"这个月没人买"本身就是需求信息。

**操作**：摘自 [src/split.py](src/split.py)：

```python
grid = skus.merge(pd.DataFrame({"月份": months}), how="cross")        # 每个 SKU × 每个月
agg = demand.groupby(["SKU", "下单月份"], as_index=False)["数量"].sum()
panel = grid.merge(agg, on=["SKU", "月份"], how="left").fillna({"需求量": 0})
```

**例子**：SKU00302 在 2025-12 到 2026-06 的需求量依次是 0、113、8、17、19、2、8。2025-12 没有非退货订单行，面板里这一行需求量记 0，而不是缺失。

## 为什么按时间切，不随机切？

如果随机抽一部分月份做评估，模型训练时就能"看到"评估月之后的数据，评估结果会比真实使用时好看。按时间切保证用更早的月份学、用更晚的月份检验。

| 划分 | 月份 | 行数 | 用途 |
|---|---|---:|---|
| 训练期 | 2024-07 至 2025-12 | 54,000 | 拟合模型、估计季节系数 |
| 验证期 | 2026-01 至 2026-03 | 9,000 | 比较基线和特征组合 |
| 最终评估期 | 2026-04 至 2026-06 | 9,000 | 只给 7.1 选定的最终模型评估一次 |

数字来自 [split_summary.json](outputs/split_summary.json)。最终评估期在选定方法之前不被任何步骤使用，这样它给出的误差才接近"拿到新月份后的真实表现"。

## 面板有多稀疏？

**注意**：72,000 个 SKU 月中，需求量为 0 的占 22.73%。平均每个 SKU 每月的需求量约 7.6（547,214 ÷ 72,000），而且波动很大——SKU00302 一个月 113、下个月 8。单个 SKU 的月度需求本来就难以预测准，后面看误差时要记住这个底子。
