## 怎么用这个模型出预测？

**操作**：使用入口是 [nb_11.1.ipynb](nb_11.1.ipynb)，在演示项目目录运行（换月份改 `--param MONTH=…`）：

```bash
uv run python -m dsflow.tracking.notebook "steps/11_部署与交付/11.1_交付与预测/nb_11.1.ipynb" --param MONTH=2026-07
```

它读 3.1 的面板，按 4.1 同一套定义算出 2026-07 每个 SKU 的特征；季节系数用模型文件里保存的训练期估计值，然后套用模型系数。结果写在 [forecast_2026-07.csv](outputs/forecast_2026-07.csv)，每行一个 SKU：预测需求量、近 3 月均值、是否提前备货。

## 哪些 SKU 被标为提前备货？

规则（演示用，未经业务确认）：预测需求量 ≥ 近 3 月均值 × 1.3，且预测需求量 ≥ 10。按这条规则标出 42 个：办公通用物资 31 个、电力物资 6 个、MRO工业品 5 个。

**例子**：SKU00302（办公通用物资）2026-04 至 06 的需求量是 19、2、8，近 3 月均值 9.67。预测 15.07，既 ≥ 9.67 × 1.3 = 12.57，又 ≥ 10，所以标为提前备货。

## 这条规则漏掉了谁？

**注意**：模型会把近期需求量高的 SKU 往长期水平拉（见 7.1）。近 3 月均值 ≥ 20 的 135 个 SKU，预测全部低于近 3 月均值，达不到 × 1.3 的门槛；被标出的 42 个 SKU，近 3 月均值最高只有 10.67。

**例子**：SKU00786（办公通用物资）近 3 月均值 45，预测 17.21，远低于门槛 58.5，没有被标出——可它是 2026-07 预测需求量排第二的 SKU。

**业务含义**：现在的规则回答的是"哪些 SKU 下月可能比近期多"，不是"哪些 SKU 下月需求量大"。如果备货关心的是量，更合适的规则可能是按预测需求量排名取前若干个，这要和业务一起定。
