# 接入指南：让 AI agent 用上 DSFlow（写给第一次用的人）

你只需要做五步。做完以后你只和 agent 对话，打开网页就能看到项目的最新情况，审批在网页上点一下。

本文假设你没有装过 Python、也没用过命令行。每一条命令都写清楚了**在哪里运行**、**运行完应该看到什么**、**报错了是什么意思**。照着从上往下做，不要跳步。

> **三个词先说清楚**
> - **终端**：敲命令的黑框。Windows 上按 `Win` 键搜 `PowerShell` 打开它；本文的命令在 PowerShell 里都能直接用。
> - **PATH**：终端用来找命令的目录清单。一个程序装好了却提示"不是可执行程序的名称"，通常就是它不在 PATH 上，或者装完没有重新打开终端。
> - **虚拟环境**：一个项目专用的 Python 目录（本文里就是项目下的 `.venv`）。分析用的库装在里面，不会和别的项目打架。

## 第一步：安装

### 1.1 先选一种装法

四种都能用，区别是**前置条件**和**之后命令怎么写**。不确定就选第一种。

| 装法 | 适合谁 | 前置条件 | 之后怎么敲命令 | 你的项目登记在哪 |
|---|---|---|---|---|
| **① uv 装成命令**（推荐） | 大多数人 | uv、Git、Node.js | 任何目录直接敲 `dsflow …` | `~/.dsflow` |
| **② 不用 uv：venv + pip** | 已经有 Python、不想再装 uv 的人 | **自己装的 Python 3.13 或更新**、Git、Node.js | 先激活虚拟环境再敲 `dsflow …`，或者写 `python -m dsflow …` | `~/.dsflow` |
| **③ 别人给你一个 `.whl` 文件** | 只想用、不想碰源码的人 | 只要 uv（或 Python 3.13+）。**不用 Git、不用 Node.js** | 任何目录直接敲 `dsflow …` | `~/.dsflow` |
| **④ 在源码仓库里跑** | 要改 DSFlow 本身的人 | uv、Git、Node.js | **必须在仓库目录里**写 `uv run dsflow …` | `<仓库>/.dsflow_home` |

> 最后一列要留意：装法 ④ 的平台目录和前三种不是同一个。用装法 ④ 建的项目，换成装法 ① 打开平台时列表里是空的——项目文件没丢，只是没登记到那个平台目录，`dsflow attach <项目目录>` 重新登记一次就回来了。

### 1.2 前置条件

按你选的装法装好对应的东西。每一样都给了验证命令：**在终端里敲它，能打印出版本号就算装好**。

| 要什么 | 哪种装法要 | 干什么用 | 怎么装 | 验证命令 | 本文验证过的版本 |
|---|---|---|---|---|---|
| **uv** | ①③④ | 安装和运行 dsflow。它会自己准备 Python，你不用另外装 | Windows PowerShell：`powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 \| iex"`<br>macOS / Linux：`curl -LsSf https://astral.sh/uv/install.sh \| sh`<br>**装完关掉终端重新打开** | `uv --version` | 0.11.14 |
| **Python** | 只有 ② 要 | 运行 dsflow 本身 | https://www.python.org/downloads/ ，安装时勾上 "Add python.exe to PATH" | `python --version` | 3.13.9（**必须 3.13 或更新**） |
| **Git** | ①②④ | 把源码取下来 | https://git-scm.com | `git --version` | 2.54.0 |
| **Node.js** | ①②④ | 只在安装时把网页构建一次 | https://nodejs.org ，选 LTS 版本 | `node --version`、`npm --version` | v24.15.0、npm 12.0.2（**Node 要 20 或更新**） |

关于版本，有三件事值得先说：

- **uv 太老会缺 `uv tool install` 这个子命令**。如果 [1.3 安装](#13-安装) 里那条命令报 `unrecognized subcommand`，先运行 `uv self update` 再来。
- **装法 ① ③ 不用你自己装 Python**，uv 会准备一个 3.13 以上的解释器。只有装法 ② 要你自己装，而且必须 3.13 或更新：Python 3.12 装到一半会停在 `ERROR: Package 'dsflow' requires a different Python: 3.12.x not in '>=3.13'`。
- **`npm` 是装 Node.js 时自带的，不用另外装 pnpm**。本文用 `npm`；你如果已经在用 `pnpm`，把命令里的 `npm --prefix web install` 换成 `pnpm --dir web install`、`npm --prefix web run build` 换成 `pnpm --dir web build` 就行，效果一样。

> DSFlow 还没有发布到 PyPI。PyPI 上那个叫 `dsflow` 的是别人的包，**不要** `pip install dsflow`，装了也不是这个平台。

### 1.3 安装

**装法 ①（推荐）**：在终端里逐条运行。第三条要下载前端依赖，一到两分钟没有新输出是正常的，别以为卡死了。

```bash
git clone https://github.com/ac0033/dsflow.git dsflow-src
cd dsflow-src
npm --prefix web install
npm --prefix web run build
uv tool install ".[mcp,chat]"
```

第一次用 uv 装工具的人，命令目录还不在 PATH 上。运行下面这条，然后**关掉终端重新打开**：

```bash
uv tool update-shell
```

**装法 ②（不用 uv）**：前四条和上面一样（`git clone`、`cd`、两条 `npm`），然后建一个虚拟环境把 dsflow 装进去：

```bash
python -m venv .dsflow-venv
.dsflow-venv\Scripts\activate          # macOS / Linux：source .dsflow-venv/bin/activate
pip install ".[mcp,chat]"
```

这种装法下，**每次开新终端都要先运行那条 `activate`**，`dsflow` 才找得到；不想每次激活就用完整路径，例如 `D:\dsflow-src\.dsflow-venv\Scripts\dsflow.exe doctor`。命令也可以写成 `python -m dsflow doctor`，效果一样。

**装法 ③（`.whl` 文件）**：不用克隆、不用 Node.js，一条命令。`.whl` 从 [Releases 页](https://github.com/ac0033/dsflow/releases) 下载，或由别人用 `uv build --wheel` 构建后发给你；把文件名换成你拿到的那个：

```bash
uv tool install "dsflow-0.31.0-py3-none-any.whl[mcp,chat]"
uv tool update-shell        # 第一次用 uv 装工具才需要，运行完关掉终端重新打开
```

想把 DSFlow 给同事用，就在自己这边运行 `uv build --wheel`，把 `dist/` 里生成的 `.whl` 发给他，他按装法 ③ 装——网页、模板、skill 都在这个文件里。

**装法 ④（要改 DSFlow 本身）**：不装成命令，在仓库目录里运行：

```bash
uv sync --extra mcp --extra chat
npm --prefix web install
npm --prefix web run build
```

这种装法下，本文所有 `dsflow …` 都要写成 `uv run dsflow …`，**并且要在仓库目录里运行**，项目目录用绝对路径传给它（例如 `uv run dsflow init D:\work\我的项目 --name 名称`）。`uv run dsflow ui --dev` 是前端热更新模式（http://127.0.0.1:5173，用 pnpm 或 npm 起 Vite，哪个有用哪个）。它的平台目录是 `<仓库>/.dsflow_home`，和前三种装法的 `~/.dsflow` 不是同一个。

### 1.4 装完检查

重新打开终端，先离开源码目录，再检查（装法 ④ 例外：留在仓库目录里，命令写成 `uv run dsflow --version`、`uv run dsflow doctor`）：

```bash
cd ..
dsflow --version
dsflow doctor
```

安装过程中出现黄色的 `warning:` 行（例如 `Failed to hardlink files; falling back to full copy`）不用管，那是 uv 在说它换了一种复制方式，不是报错；只有 `error:` 才是失败。

`dsflow doctor` 逐项检查安装是否完整。三种记号要分清：`✓` 是正常，`!` 是提示（**不是要修的项**，例如"平台服务没有在运行"），`✗` 才是要修的，每条 `✗` 下面都写着修法。最后一行看到 **"0 项要修"** 就可以往下走。

### 1.5 安装报错对照表

| 你看到的报错 | 它的意思 | 怎么修 |
|---|---|---|
| `dsflow: 术语 'dsflow' 不会被识别为 cmdlet、函数、脚本文件或可执行程序的名称。`（PowerShell）<br>`dsflow: command not found`（macOS / Linux、Windows 上的 Git Bash） | 命令不在 PATH 上 | 装法 ①③：运行 `uv tool update-shell`，**关掉终端重新打开**；装法 ②：先运行 `activate`，或者改用 `python -m dsflow …` |
| `FileNotFoundError: Forced include not found: …\web\dist` | 跳过了"构建网页"那两条 `npm` 命令 | 回到 `dsflow-src` 目录，运行 `npm --prefix web install` 和 `npm --prefix web run build`，再重新安装 |
| `ERROR: Package 'dsflow' requires a different Python: 3.12.x not in '>=3.13'` | 装法 ② 用的 Python 太老 | 装 3.13 或更新的 Python，用它重新建虚拟环境；或者改用装法 ① |
| `OSError: [Errno 2] No such file or directory: …\anthropic\types\beta\…` | 装法 ② 在很深的目录里安装，Windows 又没开长路径支持，文件名超长 | 把 `dsflow-src` 放到浅一点的目录（例如 `D:\dsflow-src`）重装，或者改用装法 ①（uv 不受这个限制） |
| `无法加载文件 …\Activate.ps1，因为此系统上已禁用脚本运行。` | 装法 ② 独有：PowerShell 的执行策略不让运行本地脚本 | 在同一个窗口先运行 `Set-ExecutionPolicy -Scope Process RemoteSigned`（只对这个窗口生效），再激活；或者干脆不激活，命令一律写成 `.dsflow-venv\Scripts\dsflow.exe …` |
| `unrecognized subcommand 'tool'` | uv 太老 | `uv self update` 后重试 |
| `error: Failed to clone …` | 网络到不了源码仓库 | 换网络，或者让给你仓库地址的人改发一个 `.whl` 文件，走装法 ③ |

### 1.6 以后怎么更新

在 `dsflow-src` 里 `git pull`，重新构建一次网页（`npm --prefix web install && npm --prefix web run build`），再按你的装法重装一次：装法 ① 是 `uv tool install ".[mcp,chat]"`，装法 ② 是激活虚拟环境后 `pip install ".[mcp,chat]"`，装法 ③ 是拿到新的 `.whl` 再 `uv tool install`，装法 ④ 是 `uv sync --extra mcp --extra chat`。项目里挂的 dsflow 指向平台自己那一份，平台升级后项目不用重新挂。

## 第二步：打开平台

```bash
dsflow ui
```

浏览器会打开 `http://127.0.0.1:8790`（不想自动开浏览器就加 `--no-browser`）。**这个终端窗口要一直开着**，关掉平台就停了；agent 写的每个文件，网页刷新就能看到。

后面的命令在**另一个终端**里运行。新开的终端同样能用 `dsflow`（装法 ② 记得先 `activate`）。

打不开网页时看这三条：

- 终端里如果写着 `端口 8790 已被其他程序占用，请换一个`，就按它说的换：`dsflow ui --port 8791`，网址里的端口也跟着换。
- 浏览器显示"无法连接"，先确认第一个终端还开着、没有报错。
- 终端里写着 `前端尚未构建`，说明第一步的两条 `npm` 命令没跑成：回 `dsflow-src` 补跑，再重新安装一次。
- 公司电脑装了代理软件时，浏览器可能把 `127.0.0.1` 也走代理，出现 502。把 `127.0.0.1` 和 `localhost` 加进代理的例外列表。

## 第三步：准备项目目录

先 `cd` 到你放项目的地方（**不要在 `dsflow-src` 里面建项目**）。

新项目：

```bash
dsflow init 我的项目 --name "月度需求预测"
```

它做三件事：用模板建好项目目录、把项目登记到平台、**准备好分析环境**。分析环境就是 agent 将来执行代码用的那个 Python：它在项目里建 `.venv`，装上 pandas、matplotlib、scikit-learn、openpyxl，再把平台自己的 dsflow 挂进去。第一次要联网下载，网好的时候一分钟左右，网慢会久一些，屏幕上会逐条打印进度。

- 这一步要联网。没联网也不会白做：项目已经建好了，屏幕会提示你联网后补一条 `dsflow attach 我的项目 --venv`。
- 已经有自己的环境、不想让它装：加 `--no-venv`。但要知道后果——agent 执行 notebook 时会用平台自己的解释器，那里没有 pandas，会报 `ModuleNotFoundError: No module named 'pandas'`。
- 想换分析库：先 `--no-venv` 建项目，再自己在项目目录里 `uv venv`、装你要的库，最后运行 `dsflow attach 我的项目 --venv` 把 dsflow 挂进去。

已经有的项目目录（里面要有 `dsflow.yaml`；没有就先用 `dsflow init` 建一个，再把数据搬进去）：

```bash
dsflow attach 我的项目 --venv
```

这一步会在项目目录里放好 `AGENTS.md`（agent 的工作规则）、`CLAUDE.md`、一个 skill、一个改讲解时自动体检的 hook，并把项目登记到平台。原始数据放进 `data/raw/`，这个目录 agent 只能读不能改。

建完检查一下，`dsflow doctor 我的项目` 会把接入文件和分析环境逐项列出来。

想先看一遍整条链再接真实的 agent：

```bash
dsflow demo
```

它在当前目录下建一个演示项目 `dsflow-demo`，并打印三步：打开哪个网址、另一个终端跑哪条命令、点了「通过」会发生什么。三分钟，不需要任何模型。

演示项目不执行代码，所以 `dsflow demo` 不给它建分析环境；`dsflow doctor dsflow-demo` 因此会把「接入 · 分析环境」列成要修的项。看完演示就想在这个项目上接真实的 agent，先补一条 `dsflow attach dsflow-demo --venv`。

## 第四步：把 agent 连上

按你用的 agent 选一种。每一种给的都是同一套工具，选一种就够。

| 你用的 agent | 怎么连 |
|---|---|
| **Claude Code** | 在项目目录启动 `claude` 即可：它自动读 `CLAUDE.md` 和项目里的 skill。想让它用工具而不是命令行：`dsflow attach 我的项目 --mcp`（写好 `.mcp.json`），或 `claude mcp add --transport http dsflow http://127.0.0.1:8790/mcp` |
| **Codex CLI** | 在 `~/.codex/config.toml` 加：<br>`[mcp_servers.dsflow]`<br>`command = "dsflow"`<br>`args = ["mcp"]`<br>它也会读项目里的 `AGENTS.md` |
| **Cursor** | 项目里建 `.cursor/mcp.json`：`{"mcpServers": {"dsflow": {"url": "http://127.0.0.1:8790/mcp"}}}`，或用 `command: "dsflow", args: ["mcp"]` |
| **Claude Desktop 等只支持本机 MCP 的** | 在它的 MCP 配置里加 `{"command": "dsflow", "args": ["mcp"]}` |
| **远程 / 云端 agent** | 平台用 `dsflow ui --host 0.0.0.0 --token 一串随机字符` 启动，把 `http://你的地址:8790/mcp` 和令牌给它（请求头 `Authorization: Bearer 令牌`）。**不要把这个地址直接暴露在公网**：放在内网、VPN 或反向代理后面 |
| **只有 shell、不支持 MCP 的** | 什么都不用配：`AGENTS.md` 里写了命令。看工具清单用 `dsflow protocol`（人读的摘要），给机器读加 `--format json`；调用写成 `dsflow call <工具> --args '<json>' -p 项目目录`，返回一行 JSON |
| **不想另装 agent** | 用自带的终端客户端：`dsflow chat 我的项目`。进去先配模型：`/models add 我的模型 --preset deepseek --api-key sk-…`（预设有 anthropic / openai / deepseek / qwen / moonshot / zhipu / openrouter / ollama，也可以用 `--provider`、`--base-url`、`--model` 手填），然后直接对话。密钥存在平台目录的 `models.json`（默认 `~/.dsflow`，环境变量 `DSFLOW_HOME` 可以改到别处），也可以写成 `env:变量名` 从环境变量取 |

> MCP 是各家 agent 之间通用的工具接口。配置文件的位置以各家当前的文档为准，上面给的是常见写法。用装法 ② 时，把表里的 `"command": "dsflow"` 换成虚拟环境里 `dsflow.exe` 的完整路径，因为那些 agent 启动时不会替你运行 `activate`。

## 第五步：一句开场白

把这句话发给 agent（在项目目录里）：

> 这个项目用 DSFlow 追踪。先读 AGENTS.md，动手之前调 `next`，按它返回的 tool_calls 做；主 agent 和执行 agent 两个角色都由你担任；交完计划或验收报告就停下来等我在网页上审批。

然后就是正常对话：告诉它业务目标和数据在哪，它会先给计划。

**第一句话之后 agent 先做两件事**：一是**开工前先检查环境**——它调 `env_check` 确认项目的 `.venv`、平台的 dsflow、pandas 这些库都到位了，缺什么它会先补齐（相当于替你跑一次 `dsflow attach 我的项目 --venv`），这样后面执行代码不会报 `No module named …`；二是按**一步是一个完整独立的单元**划分步骤——一步围绕一个完整的业务目的，有自己的产物和验收标准，不会把整个阶段堆成一步，也不会把一个操作拆成三步。你在网页上看到的第一份计划就是按这两条来的。

## 之后每一步怎么走

```
主 agent 写计划 ──▶ 你在网页上点「通过」 ──▶ 执行 agent 执行、写报告和讲解 ──▶ 主 agent 验收 ──▶ 你在网页上点「确认完成」 ──▶ 下一步
```

**「主 agent」和「执行 agent」是两个角色，不是非得两个 agent**：你不另行安排时，就是同一个 agent 依次担任这两个角色——它先给你计划，你批准后它自己执行，执行完自己回到产物上验收，再交给你确认。你想让别的 agent 干活时才分开：那时主 agent 只写计划和验收，把已批准的计划交给执行 agent。两种情形下，你要点的按钮、看到的页面完全一样。

- 网页左侧是生命周期的阶段和步骤；打开一步，页头有橙色（等你审批）或蓝色（等你确认）的条，填一句原话点按钮。
- 主 agent 交完计划后会自己等你（它在等一个文件出现），你点了按钮它就继续；你也可以在对话里直接说"通过"，它会替你记录。
- 每一步的讲解、数据、代码、运行日志、产物都在那一步的页面里；所有内容都是项目目录里的文件，你随时能打开源文件。
- 看不懂的地方直接问：在页面上选中那句话，点浮出来的「问 AI」，右侧对话框会带着这句话和它周围的原文提问；点「标注」可以就地写一句自己的备注，确认后先留在页面上不发送，标完几处再在对话框里写一个问题一起发过去，答完这几句都钉在页面上，下次进来仍然高亮。第一次用要先配模型：对话框顶部会直接显示一张表，选一家模型服务（Claude / DeepSeek / 通义千问 / Kimi / 智谱 / OpenRouter / 本机 Ollama），把密钥粘进去，点「保存并连接」，平台会真的发一句话过去测通，成功就能开始问。密钥只写进这台电脑上的 `models.json`，和 `dsflow chat` 用同一份配置，配一次两边都能用。答疑只会读项目，改不了任何文件；答案里的数字平台会回到原文里核对，找不到出处的会标出来。
- 讲解、执行计划、代码说明、报告里的行话，第一次出现时带虚线下划线，鼠标停上去就是白话解释；术语表里还没有的词，选中问 AI，答完点「收进术语表」，以后各页面都能悬停看到。

## 出问题时

- `dsflow doctor 项目目录`：安装、平台、登记、接入文件、分析环境逐项检查，每条带修法。先跑它。
- agent 报 `本轮目录 … 里没有 plan.md，没有计划就不能批准`：这一步还没有计划，不能批。让 agent 先写好 `plan.md` 再把步骤改成等审批，你再点「通过」。
- agent 好像不知道该做什么：让它运行 `dsflow next 项目目录`，那里写着现在在哪一步、缺什么文件、该做什么。
- agent 执行代码报 `ModuleNotFoundError: No module named 'pandas'`：项目没有分析环境，补一条 `dsflow attach 项目目录 --venv`。
- agent 执行 notebook 报 `No module named 'dsflow'`：项目有自己的 `.venv`，但平台的 dsflow 没挂进去，同样用 `dsflow attach 项目目录 --venv` 补。
- agent 要用的库项目里没有：在项目目录里运行 `uv pip install <库名>`；没装 uv 就用 `.venv\Scripts\python -m pip install <库名>`（`dsflow init` 建的环境里带着 pip）。库装进项目自己的 `.venv`，不影响别的项目。
- agent 改了讲解却被退回：那是体检在起作用（用词、句子、篇幅），它看到的清单就是要改的地方。
- 网页显示"没有讲解 / 没有验收报告"：说明那一步的文件还没写，不是平台坏了。
- 网页上的答疑对话框写着"还没有配置模型"：平台自己不带模型。在对话框里选一家、填密钥、点「保存并连接」；点了以后报错就照那句话改（密钥错、模型 ID 写错、地址连不上都会分别写清）。
- `dsflow chat` 里 `/models` 说 `models.json` 不是合法 JSON：它已经把坏文件挪成 `models.json.bad`，重新 `/models add` 即可。
- 平台里看不到之前建的项目：多半是换了装法（见 [1.1 先选一种装法](#11-先选一种装法) 的最后一列），`dsflow attach 项目目录` 重新登记一次。

## 不想用平台，只要这套方法

装两个 skill 就够：`skills/data-science-project`（方法与文件结构，agent 按它生成同样的目录和文件）、`skills/dsflow-project`（以后要接平台时的接口）。没有网页时，`dsflow next` 和 `dsflow check` 可以当作没有界面的平台来看进度、核对数字。
