## 0.29.0 · 每份数据都有自己的介绍，审批填错了能撤回（2026-09-20）

**起因**：两个问题——① 数据选项卡里每个数据文件下面那行小字，五份来源快照共用同一句模板话，看不出它们的差别，需要**所有项目、以后的项目**都显示这份数据自己的介绍，不是让人一个个去改；② 在平台上审批填错了没法撤回。

- **那行小字的口径定死为「这份数据的简要介绍」**：装的是什么（一行代表什么）、怎么来的、后面哪一步会用。行列数、版本、产出步骤平台自己会显示，这一句只补平台看不出来的。
- **登记时必须写**（`dsflow/data/datasets.py` 的 `register`）：第一次登记一个数据名时漏写 `description` 就登记不进来，命令行 `data add`、协议工具 `data_register`、SDK `log_output`、网页登记表单四个入口共用这一道关。唯一例外是 `run.log_input`——它记的是"这次读了谁"，读的人不一定说得清那份表，改由告警提醒补写。
- **补写不必重新登记**：新增 `dsflow data describe <项目> <名称> "<介绍>"` 与协议工具 `data_describe`（登记表从 33 个工具增加到 35 个）。
- **没写就照实说，不拿路径顶替**（`steptables.py` 的 `_entry`）：空介绍统一显示「还没有写这份数据的介绍。」并带 `note_missing`，界面上用浅一档的颜色；本轮产物原来在这一行显示相对路径，现在也走同一套。数据演变链那页同样处理。
- **漏写和雷同都报告警**（`alerts.py` 的 `_describe_alerts`）：`dataset_no_description`、`dataset_same_description` 两条警告——几份数据共用同一句话，等于谁也没介绍。
- **审批可以撤回**（`core/approval.py` 的 `withdraw` / `withdrawable`）：状态改回表态之前，审批记录里**追加**一条「撤回」，写明撤的是哪一条、为什么——记录从不删除。两条限制：只能撤最后一条；这一步的状态还得停在那条记录留下的状态，已经接着往下做了就不许撤（否则会把 agent 正在做的事从脚下抽走）。`approval_record.md` 的格式与解析同步认「撤回」。
- **agent 等待时认撤回**：`wait_for` 遇到最后一条是撤回，当作还没表态，继续等。
- **撤回在界面哪里**：还在审批条上——步骤标题下面、选项卡上面。步骤已经不在待审批 / 待验收时，这个位置留一条细条显示最近那次表态，右边就是「撤回这条」；点开先填「为什么撤回」再确认。撤不了的时候显示「不能撤回」，鼠标停上去是原因原话。
- **三种入口一致**：网页 `POST /api/projects/{id}/steps/{step}/approval/withdraw`、命令行 `dsflow withdraw . <步骤> --note "…"`、协议工具 `approval_withdraw`。
- **文档与规则同步**：`docs/agent-guide.md`（数据登记一节改写、审批一节新增撤回）、`docs/agent-protocol.md`（按登记表重新生成）、`AGENTS.md` 模板、三处 dsflow-project skill。
- **测试**：新增 6 项（介绍缺失 / 雷同的告警、小字缺失时的显示、撤回后状态与记录、状态已往前走就不许撤、撤回后 agent 继续等、撤回的接口与命令行），全量 265 项通过（另 5 项要外部样本项目，跳过）。
- **真实核对**：无头 Chrome 打开商品品名识别 1.1 的数据选项卡，8 张原存量每张下面都是各自的介绍；两个在册项目 `dsflow check` 均无介绍相关告警。
- **重新构建**：`web/dist` 与 `dist/dsflow-0.29.0-py3-none-any.whl` 重建。

## 0.28.0 · 答疑能查数据、列的变化能点开看原因、讲解多一段「结果」（2026-09-20）

**起因**：五个需求——① 答疑要能读数据、代码、产物，不能只看这一屏；② 数据选项卡要有「中间产物」，默认折叠、展开能整张打开（只放数据文件，报告与 json 不算）；③ 讲解开头要再加一段「结果」，说明做完实现了什么、产出了什么；④ 打开的数据表里除了新增列标色，原有的列被改了值也要标出来；⑤ 答疑的回答里提到代码片段与数据文件时，点一下要能跳到讲解的那一格和数据选项卡的那张表。另外，增减量里列出的列要能点开看增删与改值的原因，并和讲解联动。

- **答疑能自己查数据**（新工具 `data_query` + `data_peek` 补全列名）：`data_query` 对一份数据文件跑一条只读 SQL（表名固定 `data`，只允许 SELECT / WITH，跑在原来那个只读 DuckDB 沙箱里），用来数一数、分组汇总；没转成 Parquet 的表会如实回绝并让模型改用 `data_peek`。`data_peek` 除了前几行，现在把**全部列名**一起返回——只看 8 列写不出 SQL。答疑的系统提示改写成"需要材料就去读"，并写明各工具分别读什么。登记表从 32 个工具增加到 33 个。
- **数据选项卡新增「中间产物」**（`stock.py` 的 `_middles`）：本轮目录里留下、没进存量账的**数据文件**（核对清单、台账这类）单独一段，默认折起来，展开后每个都能「打开全貌」。markdown / json / yaml 不在这里——它们不是数据表，在「产物」里看。
- **讲解开头从五段变六段**：新增 `brief.result`「结果」，写这一步做完留下了哪些核心产出、它们现在能干什么，要和目的、操作对得上。体检把它列为必填（上限 90 字），`guide_init` 的骨架、契约 JSON、写法文档、能力 skill、AGENTS 模板、看板思维导图、答疑上下文都同步；演示项目 8 份讲解各补了一句真实的「结果」。
- **列的变化能点开看原因，并跳回讲解**（`dsflow/explain/columns.py` + `POST /api/projects/{id}/data/steps/{step}/column-notes`）：增减量里每个列名都是按钮，点开显示这一列是新增 / 消失 / 取值有变化、讲解里哪一段说过它（带原话与「问题 N · 第 M 条（单元格 K）」）、notebook 哪一格的代码写到它，右边「跳到讲解」直接落到那一格（`?tab=guide&cell=K`，那一格会高亮两秒）。讲解里查无此列就直说查不到，并给一个「问 AI」的入口，不猜理由。
- **取值变了的列也标出来**：增减量里点「看看哪些原有的列被改了值」，平台把两张表各做一遍画像再比（复用原来的对比任务），列出空值数、取值范围或不同值个数变了的那几列；这几列在「打开全貌」里标蓝、表头带「变」，新增的列仍标黄、表头带「新」。
- **答疑的回答可以点着跳**（`dsflow/ask/links.py`）：答案里出现的文件名与「单元格 N」会被认出来，核对项目里确实有这个文件之后列在答案下面——数据文件跳到那一步的「数据」并整张打开，其他文件跳到文件查看器，单元格跳到「讲解」的那一格。对不上的一律不给链接。
- **测试**：新增 6 项（只读 SQL 能数出行数 / 拒绝写语句 / 未转换时的提示、peek 给全部列名、中间产物只收数据文件、列的出处、答案里的跳转、开头必须有「结果」），全量 260 项通过（另 5 项要外部样本项目，跳过）。

## 0.27.0 · 增减量只讲变化、数据文件按阶段分流（2026-09-20）

**起因**：两个问题——① 步骤页「数据」里的增减量把整张表的全貌又铺了一遍，和后存量重复，应该改成讲「哪张表改成 / 合并成了哪张表、行和列各怎么变」；② 数据文件只在项目总览有一份长清单，想找某个阶段的文件不好索引，阶段页也该像总览那样列出本阶段的文件（含中间文件），总览则只留不属于任何阶段的文件，分类再清楚些。

- **增减量改成变化视图**（`web/src/pages/step/StepDelta.tsx`，替掉原来的表卡片网格）：每一条变化一张卡——左边是变之前的表（新增看上游表，多张就是合并；更新看自己的旧版本），右边是变之后的表，中间写「做成 / 合并成 / 重算成」；下面两行分别是**行** 121,000 → 119,998（−1,002）与**列** 12 → 15（+3），再下面把新增的列名、消失的列名各列一遍（多了可以展开全部），并写明保留几列。退出的表收成一行：`orders_raw 121,000 行 × 12 列 → 交给 orders_clean 119,998 行 × 15 列，以后不再用它`。没有可比上游表的产物（说明卡声明的那类）也收成一行，不摆变化的架子。增减量里不再有「打开全貌」，整张表在原存量 / 后存量里打开，那里打开新增的表仍会把新增的列标黄。
- **存量账补上画这张图要的数据**（`dsflow/data/stock.py`）：新增的表带 `sources`（每张上游表的名字、行数、列数），更新的表带 `previous_rows` / `previous_columns`，退出的表带 `retired_by_rows` / `retired_by_columns`。
- **顺带修掉一个数错版本的缺陷**（`dsflow/data/steptables.py` 的 `version_shape` / `version_columns` + `DataCache.parquet_for_sha`）：同一张表重算时，「旧版本」的行列数与列差原来是按**路径**读的，而那个路径上的文件已经是新版本，等于拿新版本和自己比，永远得出「列没有变」。现在按登记时的哈希找那一版的 Parquet 缓存；查不到就如实说数不出来，不拿新版本顶替。指纹本过期（比如项目被整体复制过）时，登记过的表也能按哈希找回行列数。
- **数据文件按阶段归属**（`dsflow/data/files.py` 的 `attribute`）：两条线定归属——文件放在某个步骤（或阶段）目录下，或者登记数据集时写明 `produced_by` 是本阶段的某一步。`GET /api/projects/{id}/data` 的每个文件多了 `stage` / `stage_name` / `step` / `dataset` / `data_stage`。
- **阶段页新增「数据文件」**（`web/src/pages/stage/StageFiles.tsx`，数据层第二个选项卡）：按步骤分组列出本阶段的全部数据文件（含 `data/interim` 这类由本阶段步骤产出的中间文件），每组标题写步骤名、下一行写目录、右边写文件数与合计大小。
- **项目总览的「数据文件」只留项目级的**：不再重复列阶段下的文件，清单上方写明阶段下的文件去哪看。
- **清单本身更好索引**（`FilesTab.tsx`）：分组可折叠、带文件数与合计大小，登记过的文件标出它的数据阶段（原始 / 处理后 / 特征 …），加了「只看已登记的数据集」开关，搜索照旧。
- **测试**：`tests/test_stock.py` 增两项（上游表与接手表的规模、旧版本的规模与列差），`tests/test_data.py` 增两项（阶段归属的两条线、总览接口每个文件都带归属），全量 254 项通过（另 5 项要外部样本项目，跳过）。

## 0.8.0 · 讲解改成 notebook 导读（2026-09-16）

**起因**：0.7.0 的「讲解」只是把用户报告换个排版重放一遍，等于把同一份内容读两遍；而且报告是按 agent 的思路写的，读者要的是"这一格在干什么、那个数字说明什么"。读者看 notebook 基本能看懂，卡住的是术语和"为什么这么做"。

- **讲解 = notebook 导读**（步骤页默认打开）：左边是这一轮 notebook 里真实的单元格与输出，右边是旁注——在做什么 / 为什么这样做 / 输出怎么读；不容易看懂的行加 ①②③ 行注，与代码左侧的行号对齐。
  - 顶部「30 秒看懂」：这一步要回答什么、答案、能不能继续、最多 3～4 个数字（每个都写白话含义）。
  - 按 1～3 个"读者要弄明白的问题"分段，每段末尾是业务含义；最后是「别误读：这一步没有证明什么」。
  - 内容由执行 agent 写在 `guide.yaml`（新契约 `guide`），平台只渲染与核对。
- **数字核对（讲解）**：讲解里写的每个数字，平台都回到所引用单元格的代码或输出里找一遍，页头显示「数字核对 n/m」，没找到的在旁注下方标出来。引用的 notebook、单元格、行号不存在会直接报错。
- **术语提示**：正文里第一次出现的术语加虚线下划线，悬停或聚焦看白话解释。词表优先级：本步 `terms` > 项目 `vocabulary.json` > 平台内置术语表（`dsflow/explain/glossary.yaml`，QC、主键、口径、数据泄漏、基线、MAE、holdout 等 57 条）。
- **命令行**：`dsflow guide init`（按 notebook 真实单元格生成骨架，每格列出行数与第一行）、`dsflow guide check`（核对引用与数字）、`dsflow guide put`（放到平台读得到的位置）。只读项目的导读写进平台目录，项目目录不落任何文件。
- **notebook 执行器**：`python -m dsflow.tracking.notebook <nb>` 在当前进程里逐格执行并把输出写回 notebook，不需要 Jupyter 内核；`--param 名=值` 按 papermill 的 parameters 标签注入参数，`--save-to` 另存（探索性的尝试不覆盖正式 notebook）。不支持 IPython 魔法命令。SDK 增加 `run.end()`，供 notebook 里用不了 `with` 的场景。
- **步骤页重写**：去掉右侧栏（本轮结论 / 依赖 / 轮次时间线），改成一列；选项卡按阅读顺序分组：看懂这一步（讲解、说明卡）｜怎么做的（计划、代码与 notebook、运行记录）｜做出了什么（数据变化、用户报告、验收报告）｜其他。原来的用户报告回到「用户报告」标签。
- **说明卡重写**：核心数字改成一屏卡片（处理后的大数字 + 处理前 / 变化 + 口径 + 核对状态），能说 / 不能说提到正文，其余细节收进一个展开区。
- **演示项目改成 notebook**：8 个步骤的脚本改写为 notebook（`nb_<步骤>.ipynb`），由 `dsflow run` 调执行器跑；7.1 的三次特征探索用 `--param` + `--save-to`，正式那次原地执行。模型文件内容与 0.7.0 完全一致（版本仍是 65cd04dbf982），8 张说明卡 37 个数字照旧全部一致。
- **导读实例**：演示项目 8 步各一份。

## 0.4.0 · 运行追踪（2026-09-15）

- **SDK**：`dsflow.start_run(step, hypothesis=…)` 能记录以下内容：
  - 参数；
  - 指标，支持逐折，用来看结果随切分的波动；

  - 结论与有效性：有效 / 无效 / 无结论。

- **运行记录的位置**：
  - 可写项目在 `.dsflow/runs/`，只读项目在平台目录。

- **运行与实验页**：
  - 顶部先写成功、失败、有效、无效各几次；可以按步骤、状态、有效性筛选，也可以搜索。
  - 多选对比：指标给出相对基线的带符号差值，逐折结果附均值 ± 标准差；均值差小于逐折波动时直接点明；参数不同的行高亮；输入数据版本不同时提醒对比可能不公平。
- **运行详情**：
  - 先给假设与结论，失败的给出原因和退出码。
  - 然后是指标、输入 → 输出的数据变化（可跳到完整对比）、参数、图表、产物。
  - 复现卡片：还原代码 → 还原依赖 → 核对输入数据哈希 → 重跑命令，做不到精确还原的地方如实说明。
  - 日志：运行中通过 SSE 实时追加。
- **一键重跑**：用同样的命令生成一条新的运行记录，并关联原记录。只读接入的项目不能从平台重跑，因为重跑会执行代码、写入项目目录。
- **步骤工作区**新增"运行与尝试"标签页。实际推进路径细化到每一次运行。
- **CLI**：新增 `dsflow runs`（最近的运行记录）和 `dsflow data verify`（核对数据哈希）。

## 0.3.0 · 流程图 + 步骤工作区（2026-09-15）

- **流程图**（React Flow），三种视图：
  - **依赖视图**：阶段泳道 × 执行顺序。节点先给结论：有说明卡时显示一句话结论、核心数字、关键产物，没有时显示注册表里的结论和决策。另外标出返工次数；有校验问题的节点标红。
  - **实际推进路径**：按轮次日期把各轮串起来，跳回更早步骤的用红色虚线，下方附时间线表。日期依次取自注册表、轮次目录名、主验收目录名；都没有时用文件修改时间，并注明"推断"。
  - **数据血缘**：数据集 → 产出步骤 → 数据集，自动布局。
  - 初始视野只框住有步骤的泳道；悬停一个节点时，高亮与它相连的线。
- **步骤工作区**，三栏：
  - 左栏：阶段、步骤、轮次导航。
  - 中栏标签页：说明卡、计划、用户报告、验收报告、代码与 notebook、全部文件、数据变化（复用版本对比）、轮次对比。
  - 右栏：可拖宽的侧栏，放本轮结论、依赖、轮次时间线与返工原因、校验问题。
- **步骤说明卡**（`step_card.yaml`）：
  - 首屏：结论与能否继续 → 核心数字（处理前 / 变化 / 处理后 / 口径 / 出处）→ 主要操作 → 影响判断的例外 → 产物。
  - 为什么做、必须不变、变化集中在哪里、证据、能说与不能说、下一步、例子都放在可展开区；虚构的例子会明确标注。
  - 没有说明卡时，显示注册表结论、本轮摘要和主验收报告开头。
- **报告阅读**：
  - Markdown：支持 GFM 表格、KaTeX 公式、Quarto 式提示块（**结论** / **例子** / **注意** 等），代码高亮并可复制；报告里的相对链接在平台内打开。
  - notebook：先说明执行情况（已执行几个单元、有无错误输出），代码可折叠，HTML 输出经过净化。
  - qmd：本机没有 Quarto，按源文件显示并注明未渲染。
  - html：静态显示，禁止运行脚本。
  - 图片接口带 CSP 安全头。
- **轮次文件自动分类**：计划、审批、用户报告、主验收报告、验收代码、执行记录、notebook、代码、产物、报告证据、历史操作。
- **页面按需加载**：首屏脚本从 1.18 MB 降到 312 KB。

## 0.2.0 · 数据视图（2026-09-15）

- **数据文件**：自动发现项目中的 CSV / TSV / XLSX / Parquet；CSV 自动识别 UTF-8 / GB18030 编码。
- **转换缓存**：CSV / XLSX 按内容哈希转换成 Parquet 一次，原文件不动。
  - XLSX 先用 DuckDB 直接读；遇到结构不标准或同一列类型混杂时，改用自写的流式逐行解析，内存只占一个批次，日期样式单元格还原成日期。
  - 纯整数列转为整数类型；以 0 开头的编码保留为文本。
- **浏览**：
  - 行列双向虚拟滚动，按块加载；超大表每段 20 万行，可跳到第 N 行。
  - 排序、筛选都在服务端完成；排序后保留横向位置。
  - 随机抽样，同一种子结果可复现。
  - 只读 SQL 沙箱：只能查 `data` 视图，不能读写其他文件，限 1,000 行、20 秒。
- **画像**：
  - 精确计数：非空、缺失、负值、零值、空白串。
  - 近似统计：不同值个数、分位数。
  - 分布：数值直方图（长尾明显时按 1%–99% 分位分箱，两端极端值另计）、时间按月分布、文本取值排行。
  - 结果按文件内容缓存，带版本号，格式升级后旧缓存自动重算。
- **版本对比**：
  - 结构、行数、逐列统计差；同一组分箱下两版的分布。
  - 分组影响：自动标出"变化集中"的组。
  - 主键对齐：只在 A / 只在 B / 取值改变的行、逐列变化计数与样例；主键为空的行单独计数、不参与对齐；主键不唯一时跳过逐列比对并说明原因。
- **不变量检查**：6 类——行数不变、行数变化不超过容差、合计不变、按主键原值不变、不新增缺失、主键保全。
- **数据集登记与演变链**：逻辑名 + 内容哈希版本，带阶段、上游与产出步骤；支持 dsflow.yaml 声明后一键登记。
- **CLI**：`dsflow data add | sync | list | profile | compare`。
- **资源保护**：每个 DuckDB 连接内存上限 1 GB；同时运行的重查询最多 3 个；后台任务可查看进度。
- **其他**：移除 python-calamine 依赖；演示项目新增模拟数据生成脚本。
